# [M05-D04] 마케팅 NotebookLM 보고서·슬라이드 품질 사다리 + Mixboard 확장

기준일: 2026-08-08

> 핵심 보강 + 선택 확장. NotebookLM 보고서·슬라이드는 핵심 실습, Mixboard는 빠른 학습자 선택 실습입니다.

## 이 실습팩의 위치

- 커리큘럼 연결: 동일 근거 자료를 마인드맵·팟캐스트·슬라이드·인포그래픽·보고서로 확장
- 학습 목적: 한 번 생성한 결과를 제출하지 않고 근거·대상·구조·시각·검수의 다섯 단계로 품질을 높입니다.
- 기능·명칭 보정: Mixboard는 Google Labs 실험 기능입니다. 접속·메뉴·생성 시간이 다르면 HTML 예시 평가로 전환합니다.
- 이 문서는 강사용 상세 절차와 수강생 개인 Notion 정리를 연결하는 로컬 실습자료입니다.

## 시작 전 공통 규칙

1. 교육용 가상 자료 또는 본인이 공개해도 되는 자료만 사용합니다.
2. 기능·앱·모델이 화면에 없으면 현재 상태를 기록하고 대체 실습으로 이동합니다.
3. 생성·등록·공유·취소·삭제 전에는 대상 이름을 다시 읽습니다.
4. AI 응답의 링크·출처·수치·한글·인물·제품 대응을 사람이 확인합니다.
5. 결과 전체를 공용 Notion에 붙이지 않고 개인 Notion에 최소 기록만 남깁니다.

## 실습 1. 1단계: 기본 보고서 생성

- 구분: 필수
- 권장 시간: 15분
- 준비 입력: 전날 검수한 시장·브랜드·콘텐츠 학습자료 소스
- 완료 결과: 기본 보고서와 인라인 출처

### 천천히 따라 하기

1. 준비 입력이 교육용 가상 자료인지 확인하고 실제 개인정보·기관 내부자료가 있으면 즉시 닫습니다.
2. 현재 화면에서 사용할 앱·소스·모델 이름이 실제로 보이는지 확인합니다. 보이지 않으면 추측하지 않습니다.
3. 전날 검수한 소스만 선택하고 콘텐츠 전략·캠페인 제안의 독자와 목적을 한 줄로 적습니다.
4. Report 생성 항목이 실제로 보이면 기본 보고서를 만들고 각 주장 옆의 인라인 출처를 엽니다.
5. 출처가 열리지 않거나 근거가 약한 문장을 `확인 필요`로 바꿉니다.
6. 결과를 원문·입력과 나란히 놓고 오류 한 개를 수정한 뒤 완료 질문에 답합니다.
7. 개인 Notion에 입력 요약·첫 결과·수정 이유·최종 캡처·원문 링크만 기록합니다.

### 복사해서 쓰는 프롬프트

```text
콘텐츠 전략·캠페인 제안용 기본 보고서를 만들어 줘. 배경｜핵심 사실｜문제｜대안｜확인 필요｜출처 순서로 구성해 줘.
```

### 완료 확인

- [ ] 주장마다 원문 출처를 열 수 있고 근거 없음이 표시됐는가?
- [ ] 완료 결과를 다시 열 수 있음: **기본 보고서와 인라인 출처**
- [ ] 사람이 수정한 내용과 수정 이유가 한 줄 이상 있음
- [ ] 실제 개인정보·기관 내부자료·고객자료·자격증명이 없음

### 막힐 때

제공 보고서 초안에서 근거 없는 문장 한 개를 삭제합니다.

4. 결합 또는 편집 기능이 실제로 보일 때만 실행하고 원본에 없는 로고·인물·성과 문구가 생겼는지 봅니다.
5. 원본 A·B와 결과를 나란히 두고 유지·변경·의도치 않은 추가를 세 열로 기록합니다.
6. 결과를 원문·입력과 나란히 놓고 오류 한 개를 수정한 뒤 완료 질문에 답합니다.
7. 개인 Notion에 입력 요약·첫 결과·수정 이유·최종 캡처·원문 링크만 기록합니다.

### 복사해서 쓰는 프롬프트

```text
이미지 A의 구도와 이미지 B의 색·재질 아이디어를 결합한 새 콘셉트를 만들어 줘. 원본에 없는 로고·인물·성과 문구는 추가하지 마.
```

### 완료 확인

- [ ] 두 원본의 사용 권리와 바뀐 요소를 기록했는가?
- [ ] 완료 결과를 다시 열 수 있음: **결합 이미지와 유지·변경 기록**
- [ ] 사람이 수정한 내용과 수정 이유가 한 줄 이상 있음
- [ ] 실제 개인정보·기관 내부자료·고객자료·자격증명이 없음

### 막힐 때

HTML 예시에서 A 유지 요소와 B 반영 요소를 색으로 나눕니다.

## 실습 8. Mixboard 발표용 프레젠테이션

- 구분: 선택
- 권장 시간: 20분
- 준비 입력: 완성 보드
- 완료 결과: 5장 발표 예시와 수정·공유 범위 기록

### 천천히 따라 하기

1. 준비 입력이 교육용 가상 자료인지 확인하고 실제 개인정보·기관 내부자료가 있으면 즉시 닫습니다.
2. 현재 화면에서 사용할 앱·소스·모델 이름이 실제로 보이는지 확인합니다. 보이지 않으면 추측하지 않습니다.
3. 완성 보드에서 문제→대상→근거→제안→다음 행동의 다섯 구역을 발표 순서로 정렬합니다.
4. Presentation 생성 항목이 실제로 보이면 5장 초안을 만들고 장당 메시지 하나인지 확인합니다.
5. 한 번 수정한 뒤 공유 범위를 보기로 점검하고 기능이 없으면 제공 HTML을 전체 화면으로 발표합니다.
6. 결과를 원문·입력과 나란히 놓고 오류 한 개를 수정한 뒤 완료 질문에 답합니다.
7. 개인 Notion에 입력 요약·첫 결과·수정 이유·최종 캡처·원문 링크만 기록합니다.

### 복사해서 쓰는 프롬프트

```text
이 보드를 5장 발표 구성으로 바꿔 줘. 문제｜아이디어｜선택 근거｜적용 모습｜다음 행동 순서이며 발표 초점과 시각 스타일을 먼저 확인해 줘.
```

### 완료 확인

- [ ] 보드의 맥락을 유지하고 공유 전에 가상 자료만 포함됐는가?
- [ ] 완료 결과를 다시 열 수 있음: **5장 발표 예시와 수정·공유 범위 기록**
- [ ] 사람이 수정한 내용과 수정 이유가 한 줄 이상 있음
- [ ] 실제 개인정보·기관 내부자료·고객자료·자격증명이 없음

### 막힐 때

제공 HTML 보드를 5장 제목 카드로 재구성합니다.
